# herdr 分发范式参照

> **性质：外部参照材料，不是决策。** 由另一条调研线投递，供本项目评估是否吸收。
> 对象：[`herdrdev/herdr`](https://github.com/herdrdev/herdr)，Apache-2.0，快照 2026-08-14（28.7k ★ / 2,044 fork / 建仓 4.5 个月）。
> 与本仓关系：herdr 是**分发形态同构的既有验证样本**，不是依赖、不是备选技术栈。

## 为什么值得对照

herdr 的插件分发形态与本仓 `product-definition.md` §5 收敛的形态高度同构：

| 维度 | herdr | 本仓 §5 |
|---|---|---|
| 核心 | 单 Rust binary，精瘦 | 单 skill 薄客户端 |
| 数据/清单 | `herdr-plugin.toml` 声明式清单 | `index.json` 静态索引 |
| 服务端 | 无（静态 marketplace 页面） | 无（静态托管） |
| 扩展 API | "整个 CLI 就是 plugin API，没有独立 SDK" | skill 消费 index，无专用协议 |
| 责任边界 | 明说不审查、不沙箱插件代码 | 评估者非执行者（§4） |

差别在于 herdr 已经**跑出了生态**：15+ 个第三方项目，其中 6 个在 200★ 以上（reviewr 408、file-viewer 407、collie 385、browser 301、remote 233、plus 232）。这说明"精瘦核心 + 声明式清单 + 静态目录 + 无服务端"这个形态本身足以长出第三方供给，不需要先有服务端或 SDK。这是对 §5 已有决策的**外部佐证**，不是新提案。

## 三条可直接考虑吸收的

### 1. 安装前预览确认 —— 对 §10「安全评级路线」的零成本过渡手段

herdr 的 `plugin install` 在交互终端**展示来源预览与将要执行的命令**，用户确认后才装；`--yes` 供已信任来源跳过；`--ref` 钉具体 revision。

对本仓的意义：§10 里「安全评级从 `unrated` 升级到真实扫描」是笔大投入，而**预览 + 钉版本几乎零成本，却能提供真实的安全价值**。在 security 仍为 `unrated` 的阶段，finder skill 返回候选时给出"来源 + 将执行什么 + 建议钉的 ref"，比一个假装权威的评分更诚实，也更符合 §4 的责任边界。

### 2. 责任边界的公开措辞 —— 已被社区接受的表达范本

herdr 插件文档原话（大意）：Herdr 校验清单、隔离各插件的配置与状态目录，**但不审查也不沙箱插件代码**；第三方插件来自其作者而非 Herdr，**是否运行由你决定**。

这与本仓 §4「评估者，非执行者」是同一立场，但 herdr 已经这样公开讲了，且在 28.7k★ 规模下没有引发信任反弹。本仓对外文案可直接参照这套措辞结构：**先讲我们担保什么（清单合规、信号真实），再讲我们明确不担保什么（执行安全），最后把决定权交回用户。**

### 3. skill 触发条件的负向写法

herdr 自带 skill 的 description 里写了强负向触发：「仅当用户明确提到 Herdr 时使用；**不要仅因为某任务可能受益于后台终端或并行委派就触发**」，并要求先做环境校验，不满足就直接停止。

本仓 finder skill 面临同类问题（何时该被唤起、何时不该）。这种"正向触发 + 显式负向排除 + 前置校验"的三段写法可以直接借用。

## 一条反向用法：herdr 是本仓 health 公式的绝佳测试样本

§10 记着「health 公式校准：首跑 12 源多在 99-100，区分度不足」。herdr 恰好能暴露这个盲区：

- 按**活跃度**看：近 6 周每周 55–86 commits，无衰减 —— 满分。
- 按**可持续性**看：作者 1,133 commits，第二名 13；两个作者自控 bot 的提交量超过所有外部人类贡献者之和；`CONTRIBUTING.md` 明说**不接受非邀请 PR、一律自动关闭**，只有白名单能提 PR。bus factor = 1，且社区无接管梯队。

**同一个仓，两套维度给出满分与高风险两个相反结论。** 若本仓 health 公式对 herdr 打出 99+，说明它测的是"作者有多勤奋"而不是"这东西塌了我怎么办"——而后者才是使用者真正要的信号，也才对得起"可信优先"的定位。

建议把 herdr 作为公式回归的固定测试样本之一，期望输出：活跃度高分 + 显式的单点依赖风险标记。这可能意味着 health 需要拆成至少两个不合并的维度，而不是一个复合分。
